|---|---|---|---|---|
| Контроль отклика (/health) | 5 rps, 5 мин | p95 ≤ 50 мс; ошибки ≤ 0.1% | p50/p95 latency, error rate | Источник эндпоинта: TRAINING_PR.diff `api.py` 40–42 |
| Базовый профиль POST (LLM = stub) | 10 rps, 10 мин; `diff` 10–20 КБ | p95 ≤ 250 мс; p99 ≤ 400 мс; error rate ≤ 1% | p50/p95/p99, error rate, CPU/RAM | TRAINING_PR.diff: `api.py` 35–37; `review_service.py` 19–22 |
| Пропускная способность (ramp, LLM = stub) | 5→50 rps за 10 мин, плато 5 мин | До 40 rps: p95 ≤ 350 мс; error rate ≤ 1%; на плато без падения throughput | p95, throughput, ошибки по диапазонам | Отчёт прогона (k6/JMeter) с кривой нагрузки; таблица порогов |
| Всплеск (spike, LLM = stub) | 10 rps 2 мин → 100 rps 1 мин → 10 rps 2 мин | Во всплеск p99 ≤ 900 мс; восстановление p95 ≤ 300 мс ≤ 2 мин | p95/p99, время восстановления, ошибки | Отчёт со срезами до/во время/после спайка |
| Граница (stress/capacity, LLM = stub) | Ступени 20→40→60→80→100 rps, по 3 мин | Точка насыщения ≥ 80 rps; при насыщении error rate ≤ 5% и graceful деградация | p95/p99, 5xx/таймауты по ступеням | Сводная таблица по ступеням; скриншоты метрик CPU/RAM |
| Длительная стабильность (soak, LLM = stub) | 15 rps, 60 мин | Рост RAM ≤ 10%; дрейф p95 ≤ +15%; error rate ≤ 1% | Тренды p95, ошибки, RAM/GC | Долгий прогон; сравнение начала/конца интервала |
| Размер payload (LLM = stub) | 20 rps, 5 мин при 1 КБ; затем 20 rps, 5 мин при 100 КБ | 1 КБ: p95 ≤ 180 мс; 100 КБ: p95 ≤ 280 мс; 0 таймаутов | Латентность и ошибки по профилям | TRAINING_PR.diff: prompt включает весь `diff` (19–22) |
| Смешанный профиль (70% GET, 30% POST stub) | Совокупно 30 rps, 10 мин | GET p95 ≤ 80 мс; POST p95 ≤ 300 мс; error rate ≤ 1% | Метрики раздельно по GET/POST | Разрез по кодам ответов и типам запросов |
| Деградация внешней зависимости (LLM медленный) | 1–2 rps, 15 мин; задержка LLM симулируется 5–10 c | p95 ≤ 12 c; доля таймаутов ≤ 3%; устойчивость сервиса | Энд‑ту‑энд латентность, таймауты, 5xx | TRAINING_PR.diff: внешний вызов `llm.generate` (19–22) |
| Реальный LLM (низкая параллельность) | 0.2–0.5 rps, 15 мин | p95 ≤ 8 c; таймаут ≤ 15 c; ошибки ≤ 3% | Энд‑ту‑энд p50/p95/p99, таймауты | Подтверждение внешнего вызова в TRAINING_PR.diff; отчёт прогона |

Если нагрузочное тестирование пока не требуется, обоснуйте это и назовите условие, после которого оно понадобится.

Нужно сейчас: POST /api/reviews включает синхронный вызов внешнего LLM, что создаёт высокую и вариативную латентность. Минимальные прогоны фиксируют базовые p95/p99 и устойчивость. Можно отложить только при отсутствии пользовательского трафика на POST и при использовании лишь /health; запускать при первом интеграционном трафике.
