# R.C.T.F.

- **Role:**
- Инженер по производительности, который формирует практический план нагрузочного тестирования. Пишет по-русски, кратко и проверяемо. Соблюдает формат исходного артефакта и границы доступа к файлам.
- **Context:**
- Доступны только материалы из practices/practice_01 (кроме CASE.md и README.md) для чтения.
- По TRAINING_PR.diff видно минимальный FastAPI-сервис:
  - GET /health — health-check.
  - POST /api/reviews — принимает payload с полем diff и вызывает LLM.generate().
- Для корректных нагрузочных проверок вызов LLM следует заглушить (детерминированный быстрый ответ) во избежание внешней латентности.
- Исходный артефакт tests_load.md содержит пустую таблицу сценариев.
- **Task:**
- Усилить артефакт нагрузочных проверок: заполнить таблицу сценариями (не менее 5), указать нагрузку и длительность, допустимые пределы и измеряемые метрики; оставить evidence-плейсхолдеры. Сохранить исходную структуру артефакта.
- Уточнить, что нагрузочное тестирование требуется, и обозначить условие, когда оно может не потребоваться.
- Заполнить раздел «Как использовали AI» ссылкой на данный промпт и ручные правки.
- **Format:**
- Вернуть только содержимое итогового Markdown для файла tests_load.md, совместимое со структурой исходного артефакта: заголовок, таблица, абзац про необходимость, раздел «Как использовали AI».

## Полный запрос

Сформируй усиленную версию артефакта «Нагрузочные проверки» для проекта на основе доступного контекста.

Контекст:
- Доступ к чтению: все файлы в practices/practice_01, кроме CASE.md и README.md.
- По TRAINING_PR.diff: есть FastAPI-приложение с эндпоинтами GET /health и POST /api/reviews, который принимает {"diff": "..."} и использует LLM.generate(). Для нагрузочного тестирования LLM следует заглушить (фиксированная задержка и ответ), чтобы измерять показатели сервиса, а не внешнего провайдера.
- Структура исходного артефакта practices/practice_01/tests_load.md: заголовок «Нагрузочные проверки», затем таблица с колонками «Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence», затем абзац «Если нагрузочное тестирование пока не требуется…», затем раздел «Как использовали AI» с двумя пунктами.

Задача:
1. Сгенерируй содержимое нового файла tests_load.md (будет сохранён в practices/practice_02/rctf/tests_load.md) как усиленную версию исходного артефакта без изменения его структуры: тот же заголовок, та же таблица (наполненная), тот же абзац-уточнение, тот же раздел «Как использовали AI» (заполненный).
2. В таблице перечисли минимум 5 реальных сценариев: Smoke, Baseline, Stress, Spike, Soak/Long-run. Каждый сценарий должен содержать:
   - Нагрузка и длительность: профиль RPS/конкурентности и время (например, ramp-up/plateau/ramp-down), целевой набор данных (размеры diff), и оговорку про заглушку LLM.
   - Допустимый предел: p95/p99 latency для /api/reviews при заглушке LLM, для /health — отдельный предел; error rate; доля таймаутов.
   - Что измеряем: latency (p50/p95/p99), RPS, error rate (5xx/4xx отдельно), timeouts, saturation (CPU/RAM) на уровне приложения, GC/утечки (для длительного прогона).
   - Evidence: плейсхолдеры ссылок на скрипты (например, k6) и снимки дашборда (Grafana/Prometheus), артефакты профилирования. Укажи имена файлов-скриптов как примеры (без их создания).
3. Добавь короткую фразу, что нагрузочные проверки требуются из-за потенциально высокой латентности и внешних интеграций; также укажи условие, при котором их можно отложить (например, если /api/reviews временно недоступен во внешнем контуре и используется только /health).
4. Раздел «Как использовали AI»:
   - «Строка в prompts.md»: укажи «см. experiment.md, раздел “Полный запрос”».
   - «Что проверили и исправили сами»: перечисли ручные правки (например, привязка к эндпоинтам из TRAINING_PR.diff, уточнение про заглушку LLM, реалистичные пороги).

Ограничения:
- Пиши кратко, конкретно, по-русски.
- Не добавляй новые разделы сверх структуры исходного артефакта.
- Не создавай реальные скрипты и ссылки; только понятные плейсхолдеры.
- Не ссылайся на закрытые артефакты; используй только доступный контекст.
