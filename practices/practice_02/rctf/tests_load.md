# Нагрузочные проверки

| Сценарий | Нагрузка и длительность | Допустимый предел | Что измеряем | Evidence |
|---|---|---|---|---|
| Smoke | 1–2 RPS на `/health` и `/api/reviews` по 3 мин; LLM заглушён быстрым ответом (≤5 мс) | `/health` p95 ≤ 20 мс; `/api/reviews` p95 ≤ 150 мс; error rate ≤ 0.5% | p50/p95 latency, успешность 2xx, базовая доступность | k6: smoke.js; dashboard: smoke_run.png |
| Baseline | Ramp 0→20 RPS за 2 мин, плато 10 мин, спад 1 мин; размеры `diff`: 1–5 КБ; LLM заглушён фикс. задержкой 10 мс | `/api/reviews`: p95 ≤ 200 мс, p99 ≤ 300 мс; error rate ≤ 1%; timeouts = 0 | latency p50/p95/p99, устойчивый RPS, CPU/RAM процесса, GC паузы | k6: baseline.js; dashboard: baseline_metrics.png |
| Stress | Линейный рост 20→150 RPS за 10 мин, затем до деградации 5xx>5%; `diff` 1–20 КБ; LLM задержка 10 мс | До точки насыщения: p95 ≤ 400 мс; допускается кратковременный рост p99 до 800 мс; error rate ≤ 5% | пропускная способность, ошибка по типам (4xx/5xx), очереди, saturation CPU | k6: stress.js; dashboard: stress_breakpoint.png |
| Spike | Резкие всплески 0→100 RPS на 30 с каждые 2 мин (5 волн); `diff` 10 КБ; LLM задержка 10 мс | В течение 60 с после спайка: восстановление `/api/reviews` p95 ≤ 250 мс; error rate ≤ 2% | устойчивость к спайкам, колебания латентности, повторные ошибки | k6: spike.js; dashboard: spike_recovery.png |
| Soak (длительный) | Стабильно 10–15 RPS в течение 60 мин; `diff` распределение 1–50 КБ; LLM задержка 10 мс | Стабильность p95 ≤ 220 мс, p99 ≤ 350 мс на всём интервале; error rate ≤ 1%; отсутствие деградации ресурсов | тренд latency, error rate, утечки памяти, рост GC-пауз | k6: soak.js; dashboard: soak_trends.png; heap: soak_heap.flame |

Если нагрузочное тестирование пока не требуется, обоснуйте это и назовите условие, после которого оно понадобится.

Требуется сейчас: сервис имеет внешний вызов LLM у `/api/reviews`; без заглушки латентность неуправляема. Даже при пилоте важно подтвердить базовые p95/p99 и устойчивость к спайкам. Можно отложить только если используется один `/health` без пользовательского трафика и POST `/api/reviews` недоступен конечным пользователям; запускать сразу при первом внешнем трафике или интеграционном контуре.

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): см. experiment.md, раздел «Полный запрос»
- Что проверили и исправили сами: привязали сценарии к эндпоинтам из TRAINING_PR.diff (`/health`, `/api/reviews`), добавили требование заглушать LLM с фиксированной задержкой, уточнили реалистичные пороги p95/p99 и error rate, оставили evidence как плейсхолдеры без создания файлов.
