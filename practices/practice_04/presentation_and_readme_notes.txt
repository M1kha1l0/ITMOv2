Презентация: извлечённый текст (заметки слайдов) и конспект

Источник: presentation.pptx (текст в основном хранится в ppt/notesSlides/*) и README.md текущей практики.

Содержание заметок (основные тезисы):

1) Организация занятия
- 90 минут, 6 этапов. Большую часть времени семинарист показывает работающий OpenCode. Слайды — пошаговые действия и контрольные точки.
- Команды и примеры рассчитаны на OpenCode 2.0.20.
- Перед стартом: OpenCode установлен, доступ к модели работает, есть свой проект и команда проверки. Используем бюджет курса, не тратим время на установку всего подряд.
- Есть расписание по этапам с временем на объяснение, действия и проверку; при блокерах фиксируем их и используем запасной вариант из соседнего слайда.

2) Выбор задач A и B
- Выбрать две небольшие фичи и критерии приёмки. При отсутствии приложения — резервный учебный каркас ведущего (FastAPI) только как пример.
- Пример A: входная валидация. Пример B: ограничение ожидания зависимости. Конкретные коды/лимиты — из требований вашего проекта.
- Для демо A: валидация diff. Размер >20000 должен давать 413; pydantic max_length (422) недостаточен. MCP даёт справку, тест подтверждает поведение. Если A слишком велика — сузить задачу.

3) Практика Git и запуск окружения
- Показывать путь и ветку до запуска агента. Проверить, что opencode.json не потерялся из-за .gitignore (git ls-files opencode.json).
- Для Python — новая .venv и установка requirements; для иных стеков — привычный способ установки.
- Не делать git add . вслепую — перечислять конкретно нужные файлы; не использовать git reset --hard. Без зелёной итоговой проверки не объявлять обе фичи завершёнными.
- Показать граничный сценарий и что неправильный запрос не дошёл до fake LLM.

4) OpenCode 2.0.20 — ключевые нюансы
- config.instructions сохраняется для совместимости, но не применяется. Устойчивые инструкции — в AGENTS.md; style guide явно указывать там и в поручении.
- Skills: хранить пакет в .opencode/skills/<id>/SKILL.md, API skill.list показывает обнаруженные. Главная проверка — фактическое применение skill моделью.
- MCP: конфиг через mcp.servers и disabled. mcp list проверяет подключение, не доказывает применение. Для учебного показа у context7 codemode:false (прямые видимые tools).
- Agents: agent create/agent list отсутствуют в 2.0.20. Поддерживается .opencode/agents/tester.md; после добавления — reload. Список может быть пуст на самом первом запросе — дождаться и повторить.
- Subagent: делегирование задач. Не путать run --agent (вызов первичного) с дочерним поручением. Разрешения subagent и доступы дочерней роли проверяются отдельно; наличие профиля не доказывает вызов — сверяем отчёт с действиями и кодом.

5) Hook/Plugin API и автоматическая проверка
- Новый plugin API: default export с id и setup(ctx), регистрация через ctx.tool.hook.
- Для завершённых write/edit/patch выполняется check.sh; его вывод добавляется к результату tool, событие и exit code пишутся локально (без содержимого исходников). Hook не вызывает OpenCode повторно и не изменяет код.
- Сначала ручная проверка runner; затем агент делает тестовое изменение, показываем фактический вызов callback и результат.
- В plugin list ID «-» означает обнаруженный файл, но не успешную загрузку — нужен настоящий ID и событие выполнения.

6) Skills и каталог
- Навигационный каталог — не гарантия качества. TDD skill с writing-good-tests.md использован в репетиции; webapp-testing — документированный пример, не запускался в FastAPI-сценарии.
- Перед установкой читаем содержимое skill; не удаляем существующий код студента ради общих инструкций TDD.

7) Итоги и передача (handoff)
- Не нужен полный архив чата. Разделяем происхождение требований, каркаса и изменений A/B; просим другую сессию пересказать handoff.
- Итог — по фактам, без обязательной «положительной» оценки AI. Если не успели — честно делим на выполненное, наблюдённое и оставшееся.

8) Домашнее и границы занятия
- Можно продолжить учебный проект или автоматизировать другую задачу; сделанное на семинаре засчитывается.
- Собственный MCP обязателен в ДЗ; подключение готового его не заменяет.
- Не прикладывать секреты или всю историю переписки. Нужна понятная точка входа; запуск всего проекта необязателен. Срок объявляет преподаватель.
- LSP: в 2.0.20 по migration guide ещё не исполняется — не ставим языковые серверы ради неработающего подключения. AST-index — отдельный CLI; на небольшом проекте достаточно rg и команды проверки.

9) Оценивание (10 баллов: 5+2+2+1)
- 5: применённые AGENTS.md, skill, MCP, hook и обоснование подключений — по 1 баллу, с наблюдаемым подтверждением.
- 2: skill — устройство/автоматизация (1) и запуск с проверенным результатом (1).
- 2: собственный MCP — полезный tool (1) и реальный вызов, включая ошибочный вход (1).
- 1: свободная рефлексия в reflection.md.

- Настроить среду и показать её применение: агент читает AGENTS.md, загружает выбранный skill, вызывает MCP tool; автоматическая проверка запускается после правки и возвращает результат агенту. Обосновать подключения.
