Правила работы агента (practice_04)

Роль агента
- Пользователь формулирует Идею и Acceptance Criteria. Код, архитектурные изменения и тесты пишет агент.

Интеграции
- Skill: practice04.tdd (TDD, сначала тесты, затем код).
- MCP server: practice04 с инструментами validate.input и weather.features.
- Plugin hook: practice04.checks — после write/edit/patch запускает scripts/check.sh (pytest). Если тесты красные — остановиться и исправить.

Стиль и ограничения
- Минимальные изменения: без широких рефакторингов, менять только необходимое для выполнения задачи.
- Изменения держать в рамках существующих модулей (предпочтительно main.py, app/config.py, app/weather.py), выносить в новые файлы только при явной необходимости.
- Сначала дописать/обновить тесты (tests/*) под Acceptance Criteria, убедиться, что они падают, затем сделать правки кода до зелёных тестов.
- Не использовать разрушительные Git-команды (reset --hard и т.п.). Коммиты атомарные и по делу.
- Не удалять существующий код студента ради общих практик.

Архитектурные принципы
- Расширение регионов/культур — через app/config.py (REGIONS/CROPS) и параметризацию prompt; избегать спутывания слоёв.
- Валидация входа — явная (ValueError), сообщения понятные.
- Парсинг дат — строго dd-mm-yyyy; на ошибки отвечать понятным текстом и кодом выхода.

Проверка
- После каждого изменения запускать scripts/check.sh (hook делает это автоматически). Продолжать работу только при зелёных тестах.
- Для демонстрации ограничений входа использовать MCP validate.input (ожидаемый 413 при diff_size>20000).
- Для извлечения погодных фактов использовать MCP weather.features при необходимости.

Формат поручений от пользователя
- Пользователь даёт краткую «Идею» и «Acceptance Criteria». Агент сам: пишет/обновляет тесты, минимально меняет код, запускает проверки, показывает итог.
