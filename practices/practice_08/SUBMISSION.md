## 3. Описание использования AI и исправления тимлида

### 1. Проектирование макета:
* **Промпт AI:**  
  *«Спроектируй макет веб-интерфейса для классификации GitHub Issues поверх n8n. Покажи форму создания обращения, поток обработанных задач с бейджами типов (bug, feature, task, needs-triage), блок метрик и модальное окно деталей. Реализуй на Tailwind CSS с поддержкой переключения состояний: initial, validation, loading, success, error, empty.»*
* **Что сгенерировал AI:**  
  Интерактивный HTML-файл с базовой формой и списком карточек.
* **Что исправил и улучшил тимлид:**
  1. Добавил верхнюю панель-контроллер состояний макета (`mockup.html`), позволяющую ревьюверу в 1 клик посмотреть любой экран (включая ошибку 500 и пустой список).
  2. Добавил семантическую цветовую схему для 4 типов Issues, соответствующую логике из n8n Практики 7.2.
  3. Исправил отступы и выстроил адаптивную 12-колоночную сетку (5 колонок форма, 7 колонок лента).

### 2. Реализация компонентов и интерфейса:
* **Промпт AI:**  
  *«Разработай React-компоненты на TypeScript с использованием Tailwind UI patterns. Создай переиспользуемые Button, Input, Textarea, Badge, Card, Alert, Modal. Добавь форму с валидацией и защиту от повторной отправки при двойном клике.»*
* **Что сгенерировал AI:**  
  Набор компонентов и форму с хуками `useState`.
* **Что исправил и улучшил тимлид:**
  1. **Anti-Double-Submit Gate:** AI первоначально просто ставил `disabled` на кнопку, что не защищало от повторного нажатия клавиши `Enter` в текстовом поле во время активного запроса. Добавлен строгий флаг `isSubmitting` в обработчик `handleSubmit`, прерывающий любые повторные вызовы до разрешения промиса.
  2. **Доступность (Accessibility / a11y):** Добавлены `aria-invalid`, `aria-describedby` для полей с ошибками, явные `<label htmlFor="...">`, а также поддержка закрытия модалки по клавише `Escape`.
  3. **Обработка Retry:** При ошибке API 500 сохраняется объект неудачного запроса (`lastFailedRequest`), позволяя пользователю нажать кнопку «Повторить попытку (Retry)» без повторного набора текста.

### 3. Написание тестов:
* **Промпт AI:**  
  *«Напиши тесты на Vitest + Testing Library, проверяющие двойную отправку, валидацию полей, состояния интерфейса и сквозной сценарий пользователя.»*
* **Что сгенерировал AI:**  
  Черновики тестов с моками `fetch`.
* **Что исправил и улучшил тимлид:**
  1. Исправил конфликт селекторов `getByText(/94%/i)` и `getByRole('button', { name: 'Закрыть' })`, где один селектор находил несколько элементов в DOM (в алерте и в карточке / модалке), сделав запросы точечными через `within(dialog)` и `getAllByText`.
  2. Настроил чистый сброс моков `beforeEach(() => vi.restoreAllMocks())` и хук очистки DOM `afterEach(cleanup)`.
  3. Разделил тесты на 5 изолированных файлов строго по критериям 7–11 для прозрачности проверки.
