# IssueTriage AI: Клиентский интерфейс сервиса классификации GitHub Issues поверх n8n (Практика 8)

Интерфейс веб-сервиса автоматического триажа, категоризации и аналитики GitHub Issues, взаимодействующий с Sub-workflow и сценариями n8n, разработанными в рамках Практики 7.2.

---

## 🚀 Быстрый старт

### 1. Установка зависимостей
Требуется **Node.js 18+** и **npm**:
```bash
npm install
```

### 2. Запуск приложения в режиме разработки
```bash
npm run dev
```
Приложение откроется локально по адресу `http://localhost:5173`.

### 3. Сборка продакшн-бандла
```bash
npm run build
```

### 4. Запуск автоматических клиентских тестов
```bash
npm test
```
Тесты запускаются в среде Vitest + JSDOM + Testing Library и покрывают все 5 обязательных критериев тестирования.

## 🎨 Библиотека компонентов и дизайн-система

- **Библиотека компонентов:** **Tailwind UI + Headless UI patterns + Lucide React**.
- **Каталог переиспользуемых UI-компонентов (`src/components/ui/`):**
  - `Button`: варианты `primary`, `secondary`, `danger`, `ghost` с поддержкой спиннера загрузки, состояния `disabled` и клавиатурного фокуса (`focus-visible:ring-2`).
  - `Input` и `Textarea`: доступные поля ввода с подписями (`<label>`), текстом подсказки, подсветкой ошибок и атрибутами `aria-invalid` / `aria-describedby`.
  - `Badge`: семантическая цветовая индикация типов Issues (`bug` — Rose, `feature` — Emerald, `task` — Sky, `needs-triage` / `unknown` — Amber).
  - `Card`: модульные карточки с разделителями, заголовками и футерами.
  - `Alert`: баннеры обратной связи (`success`, `error`, `warning`, `info`) с поддержкой действий (например, Retry) и закрытия.
  - `Modal`: модальное окно с затемнением фона (`backdrop-blur`), закрытием по `Escape` и клику на оверлей, сохраняющее фокус внутри.
- **Единое оформление (Design Tokens):**
  - **Палитра:** Нейтральная шкала Slate (50–900), фирменный акцент Indigo-600, семантические цвета статусов.
  - **Типографика:** Межбуквенные расстояния и шрифтовая иерархия Inter (H1 24px, H2 18px, Body 14px, Caption 12px).
  - **Отступы:** 4px/8px модульная сетка (`gap-4`, `p-6`, `space-y-4`).
  - **Доступность (a11y):** Полная навигация с клавиатуры (`Tab`, `Space`, `Enter`, `Escape`), видимый фокус-ринг, высокий контраст по стандарту WCAG 2.1 AA.

## 📋 Основной пользовательский сценарий

1. **Просмотр сводки:** Пользователь видит KPI-метрики по категориям (`Всего`, `Баги`, `Фичи`, `Needs Triage`) и ленту обращений.
2. **Ввод данных:** Пользователь вводит заголовок (от 5 символов) и описание (от 10 символов). Доступны пресеты быстрого заполнения (`Заполнить тестовым багом`, `Тест needs-triage`).
3. **Валидация:** При попытке отправить пустую форму отображаются понятные ошибки, поля подсвечиваются, сетевой запрос не уходит.
4. **Защита от повторной отправки (Anti-Double-Submit):**
   При первом клике или нажатии `Enter` форма блокируется (`isSubmitting = true`), кнопка переходит в режим загрузки («Классификация в n8n...»). Повторные клики и нажатия `Enter` во время ожидания сетевого ответа игнорируются.
5. **Результат и отображение:** После классификации появляется успешное уведомление, карточка Issue добавляется в верх списка с уверенностью AI и присвоенным лейблом, метрики обновляются.
6. **Детализация:** Клик по кнопке «Детали» открывает модальное окно с подробным AI-обоснованием (`reasoning`), статусом комментария и исходным текстом.
