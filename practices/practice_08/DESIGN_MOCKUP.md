> **Проект:** IssueTriage AI — Веб-интерфейс сервиса классификации GitHub Issues и аналитики поверх n8n  
> **Интерактивный макет:** [`mockup.html`](file:///home/hackerman/Documents/education/itmo/vibecoding/ITMOv2/practices/practice_08/mockup.html)  
> **Стек:** React 18 + TypeScript + Vite + Tailwind CSS + Lucide Icons + Vitest

## 1. Основной пользовательский сценарий (User Journey)

### Пользователь и его задача:
- **Персона:** Tech Lead / QA Engineer / Разработчик проекта.
- **Контекст:** В проект поступают десятки разнородных обращений. Требуется быстро проверить или отправить Issue на классификацию в n8n Sub-workflow, проставить лейблы и получить прозрачное AI-обоснование.
- **Основной сценарий:**
  1. Пользователь открывает интерфейс и видит текущие метрики (KPI) обработанных обращений и поток последних задач.
  2. Пользователь заполняет форму нового Issue:
     - Заголовок (минимум 5 символов);
     - Описание проблемы / запроса (минимум 10 символов);
     - Автор обращения (с автоматическим определением ассоциации).
  3. В процессе ввода работает «живая» валидация: при попытке отправить пустую форму или слишком короткий текст подсвечиваются поля с выводом понятных ошибок.
  4. Пользователь нажимает кнопку **«Отправить на AI-триаж в n8n»** (или нажимает `Enter`):
     - Включается защита от спама и повторных нажатий: кнопка переходит в состояние загрузки со спиннером, поля блокируются (`isSubmitting = true`). Повторные клики и нажатия `Enter` игнорируются.
  5. Запрос уходит в вебхук n8n / REST API сервиса.
  6. После успешной классификации:
     - Показывается успешное уведомление с категорией (`bug` / `feature` / `task` / `needs-triage`), процентом уверенности AI и статусом комментария;
     - Карточка появляется в начале списка обработанных Issues;
     - Счетчики метрик обновляются.
  7. Пользователь может нажать **«Детали»** на любой карточке, чтобы открыть модальное окно с полным AI-обоснованием (`reasoning`), исходным телом обращения и историей действий.

## 2. Библиотека компонентов и дизайн-система

### Выбор библиотеки:
Выбрана современная модульная дизайн-система на базе **Tailwind CSS + Headless UI patterns + Lucide React**.

**Переиспользуемые компоненты (`src/components/ui/`):**
1. **`Button`**: варианты `primary`, `secondary`, `danger`, `ghost`. Поддерживает состояния `loading` (со спиннером), `disabled`, видимый индикатор клавиатурного фокуса (`focus-visible:ring-2 focus-visible:ring-indigo-500`).
2. **`Input` / `Textarea`**: метка поля (`<label>`), текст подсказки (`hint`), текст ошибки с `aria-describedby` и `aria-invalid`.
3. **`Badge`**: семантические цвета категорий:
   - `bug` → Rose (`bg-rose-100 text-rose-800 border-rose-200`)
   - `feature` → Emerald (`bg-emerald-100 text-emerald-800 border-emerald-200`)
   - `task` → Sky (`bg-sky-100 text-sky-800 border-sky-200`)
   - `needs-triage` / `unknown` → Amber (`bg-amber-100 text-amber-800 border-amber-200`)
4. **`Alert`**: блоки обратной связи (`success`, `error`, `info`) с иконками и кнопками действия.
5. **`Modal` (Dialog)**: доступное модальное окно с затемнением фона (`backdrop-blur`), закрытием по клавише `Escape`, клику вне окна и кнопке закрытия.
6. **`Card`**: унифицированный контейнер с заголовком, границами (`border-slate-200`) и скруглением (`rounded-xl`).

### Единое оформление (Design Tokens):
- **Цветовая палитра:** Slate-50/100/200/500/700/900 для нейтральных элементов; Indigo-600 для главного акцента; семантические цвета для статусов (Rose, Emerald, Amber).
- **Типографика:** Системный стек / Inter. Строгая иерархия: H1 (24px, 700), H2 (18px, 700), Body (14px, 400), Caption (12px, 500).
- **Сетка и отступы:** Модульная сетка 4px / 8px (`p-4`, `p-6`, `gap-4`, `space-y-4`).
- **Доступность (a11y):** Все интерактивные элементы поддерживают навигацию с клавиатуры (`Tab`, `Space`, `Enter`, `Escape`), имеют высокий контраст и видимый индикатор фокуса.

## 4. Вклад AI и исправления тимлида

### Что сгенерировал AI:
1. Базовый драфт формы на Tailwind CSS в одну колонку.
2. Простой список обращений с текстовыми лейблами.
3. Базовую функцию валидации на пустоту.

### Что исправил и доработал тимлид (BigTech Quality Gate):
1. **Защита от повторной отправки (Race Conditions & Double Submit):**
   - Добавлен флаг блокировки `isSubmitting`, который мгновенно отключает кнопку отправки и поля формы при первом клике.
   - Заблокирована обработка клавиши `Enter` во время активного сетевого запроса.
2. **Семантика доступности (WCAG 2.1 AA):**
   - Добавлены явные теги `<label htmlFor="...">`, атрибуты `aria-invalid`, `aria-describedby` с привязкой к id сообщений об ошибках.
   - Реализована правильная фокусировка и закрытие модального окна по `Escape`.
3. **Обработка пограничных состояний:**
   - Добавлен полноценный **Empty State** («Нет обработанных Issue») с понятной подсказкой пользователю.
   - Добавлен **Error State** при сбое n8n с возможностью повторить запрос (Retry).
4. **Информативность триажа:**
   - Выведена шкала уверенности AI (`confidence %`), цветные бейджи для 4 категорий и флаг публикации комментария в GitHub.
