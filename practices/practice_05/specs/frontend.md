# Спецификация: Фронтенд веб-интерфейса (Команда UI)

## 1. Цель и назначение
- **Цель:** Предоставить интуитивный, адаптивный веб-интерфейс для работы с агрономической моделью оценки благоприятности посадки культур.
- **SDD Framework:** Спроектировано и зафиксировано через инструмент `git-spec` в рамках brownfield-разработки.
- **Связанный контракт:** [specs/contract.md](file:///home/hackerman/Documents/education/itmo/vibecoding/ITMOv2/practices/practice_05/specs/contract.md).

## 2. Структура интерфейса и компонентов
Фронтенд реализован на чистом стеке (HTML5, modern CSS3, Vanilla JS ES6+) без тяжелых фреймворков:
- `web/index.html` — разметка, семантика доступности (ARIA).
- `web/styles.css` — адаптивные стили (CSS Grid, Flexbox, темная тема, CSS переменные).
- `web/app.js` — модуль управления состоянием, маска ввода, валидация, обращение к API.

### 2.1. Форма ввода (Input Section)
- **Поле даты:**
  - Маска автоматического форматирования `dd-mm-yyyy` с добавлением дефисов при наборе.
  - Ограничение длины 10 символов, только цифры.
  - Быстрые пресеты дат («15 мая 2026», «1 июня 2026», «10 апр 2026»).
  - Клиентская валидация (проверка корректности диапазонов дня 01-31 и месяца 01-12) до отправки в API.
- **Выпадающие списки (Select):**
  - Регион: `spb` (Санкт-Петербург), `moscow` (Москва).
  - Культура: `tomato` (Томаты), `potato` (Картофель), `cucumber` (Огурцы).
- **Расширенные настройки модели (Collapsible `<details>`):**
  - Имя модели (по умолчанию `qwen3.5:4b`).
  - Слайдер температуры (0.0 – 1.5, шаг 0.1, отображение текущего значения).
- **Кнопка отправки:**
  - Состояние загрузки со спиннером и блокировкой от повторных нажатий (`disabled`).

### 2.2. Блок результатов (Result Presentation)
- **Вердикт:** Крупный цветной статус (`Благоприятно` — зеленый, `Неблагоприятно` — красный/янтарный).
- **Вероятность:** Процентное значение и визуальный индикатор прогресс-бара с градиентом.
- **Обоснование:** Стилизованный блок цитаты с текстом агрономического заключения.
- **Погодные факты:** Сетка карточек с ключевыми показателями:
  - Температура мин/макс.
  - Часы солнечного сияния.
  - Сумма осадков за сутки.
  - Максимальная скорость ветра.
- **Метаданные:** Координаты, таймзона и источник данных.

## 3. Обработка ошибок и состояний
- При 422: отображение понятного текста валидации под полем даты или в alert-баннере.
- При 502: уведомление о сбое внешней службы (погода или LLM).
- При обрыве связи (Network Error): сообщение о недоступности сервера.
- Индикатор статуса API в шапке: опрашивает `GET /health` при загрузке страницы.

## 4. Критерии приёмки (Acceptance Criteria)
1. **AC-UI-1:** Страница загружается корректно, статические ресурсы (`styles.css`, `app.js`) имеют HTTP статус 200.
2. **AC-UI-2:** Клиентская валидация блокирует отправку пустой или некорректной даты без лишних сетевых вызовов.
3. **AC-UI-3:** При получении 200 от `/query` все поля (`verdict`, `probability`, `explanation`, факты ERA5) отображаются в интерфейсе.
4. **AC-UI-4:** Поля запроса (`date`, `region`, `crop`, `model`, `temperature`) строго соответствуют Pydantic схеме `QueryRequest`.
5. **AC-UI-5:** Интерфейс корректно отображается как на десктопных, так и на мобильных экранах (адаптивный дизайн).
