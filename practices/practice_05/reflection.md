# Рефлексия: Практика 5 (SDD brownfield с git-spec)

## 1. Чему научились и что согласовали

1. **Эмуляция двух команд до написания кода (UI & Logic):**
   - Самый ценный инсайт практики — фиксация контракта взаимодействия ([specs/contract.md](file:///home/hackerman/Documents/education/itmo/vibecoding/ITMOv2/practices/practice_05/specs/contract.md)) до написания первой строчки кода.
   - Мы чётко разграничили ответственность: команда UI зафиксировала форму, маску даты и обработку состояний (idle, loading, success, error), а команда Logic строго зафиксировала Pydantic-схемы, HTTP-коды (422 для клиентских ошибок валидации, 502 для апстрим-сбоев погоды и LLM) и структуру ответа `QueryResponse`.
   - В результате бэкенд и фронтенд сошлись с первого раза без взаимных правок и «подгонки» полей на лету.

2. **Опыт работы с SDD-фреймворком `git-spec`:**
   - По сравнению с OpenSpec, который опирается на статичные markdown-файлы в каталоге `.openspec/`, `git-spec` использует принципиально иной подход: локальную векторную базу данных **PGlite** (Postgres в WebAssembly с расширением `pgvector`).
   - Нативная интеграция через команду Git (`git spec ...`) делает инструмент частью привычного инструментария разработчика.
   - Семантический поиск по эмбеддингам (`git spec query`) оказался крайне удобен для агента: модель получает не весь огромный файл с кодом, а компактные релевантные фрагменты функций и контрактов.

## 2. С чем возникли трудности и как они были решены

1. **Особенности индексации `git-spec` на реальном проекте:**
   - *Проблема:* По умолчанию `git-spec` пытался индексировать скомпилированные байт-файлы Python (`.pyc` в `__pycache__`), что вызывало ошибку декодирования в PostgreSQL (`invalid byte sequence for encoding "UTF8": 0x00`).
   - *Решение:* Добавили фильтрацию бинарных файлов и путей `__pycache__` в конфигурацию парсера `git-spec`.
   - *Проблема:* Дефолтное имя таблицы в `VectorStoreManager` расходилось между `index` (`codebase_index`) и `query` (`documents`), из-за чего поиск возвращал 0 результатов.
   - *Решение:* Синхронизировали имя коллекции и оптимизировали параметры `ivfflat` индекса для небольших баз данных. После этого `git spec query` стал мгновенно возвращать точные результаты.

2. **Изоляция и полнота тестирования:**
   - Для выполнения требования «полные сценарии использования, включая проверку локальных запусков» было недостаточно просто протестировать функции через unittest.
   - Мы реализовали автоматическое выделение свободного TCP-порта (`find_free_port`) и реальный запуск сервера uvicorn в фоновом потоке, что подтвердило работоспособность локального рантайма без флакающих тестов.
   - Добавили контрактный тест `test_contract_consistency_ui_and_api`, проверяющий, что JS-клиент ожидает ровно те поля, которые объявляет Pydantic-модель.
