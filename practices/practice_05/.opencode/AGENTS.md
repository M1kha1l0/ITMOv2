# Правила работы агента (Practice 05 — SDD с git-spec)

## Роль агента и процесс разработки
- Разработка ведется строго по методологии **Spec-Driven Development (SDD)**.
- До написания любого производственного кода агент обращается к спецификациям в каталоге `specs/` и общему контракту `specs/contract.md`.
- Эмуляция взаимодействия двух команд:
  - **Команда UI (Frontend):** спецификация `specs/frontend.md`, реализация в `web/` (`index.html`, `styles.css`, `app.js`).
  - **Команда Logic (API):** спецификация `specs/api-endpoint.md`, реализация в `app/api.py`.
  - **Общий контракт:** `specs/contract.md` фиксирует схемы запроса/ответа, коды ошибок (422, 502, 500) и правила валидации.

## SDD-фреймворк git-spec
- Для навигации, семантического анализа и проверки согласованности спецификаций используется инструмент `git spec`.
- При начале работ по фиче или изменению контракта:
  1. Выполнить `git spec parse <директория>` для проверки графа зависимостей.
  2. Выполнить `git spec query "<вопрос>"` для контекстного поиска по векторам в PGlite.
  3. После обновления спек синхронизировать индекс: `git spec index <директория>`.

## Интеграции и инструменты агента
- **Skills:**
  - `git-spec`: инструкции по работе с векторным индексом и подкомандами `git spec`.
  - `specs-api`: правила проектирования и доработки FastAPI-эндпоинтов без изменения доменного ядра.
  - `specs-frontend`: правила верстки, маскирования ввода даты и асинхронного взаимодействия с API.
  - `practice05.testing`: методика написания сквозных e2e-сценариев и тестов локального запуска.
- **MCP Server (`practice05`):**
  - `weather.features(date_iso, region_key)`: извлечение погодных фактов Open-Meteo ERA5.
  - `validate.input(diff_size)`: проверка допустимого объема диффа (код 413 при diff_size > 20000).
  - `api.health()`: диагностика локального API сервиса.
  - `spec.query(text)`: быстрый вызов семантического поиска по спецификациям.
- **Plugin Hook (`practice05.checks`):**
  - Автоматически запускает `scripts/check.sh` после операций `write:after`, `edit:after`, `patch:after`.
  - При красных тестах агент обязан немедленно исправить регрессию до перехода к следующим шагам.

## Стиль и архитектурные ограничения
- **Принцип минимальных изменений:** не переписывать доменное ядро (`app/config.py`, `app/weather.py`, `app/ollama_client.py`, `main.py`). CLI должен оставаться 100% работоспособным.
- **TDD и сквозные проверки:** перед кодом пишется падающий тест. Тестовый набор покрывает полные пользовательские сценарии, граничные случаи и проверку реального локального запуска сервера и CLI.
- **Разрешённый scope:** агент работает строго в пределах каталога `practices/practice_05/`. Запрещены вызовы и запись файлов за пределами текущего проекта.
- **Управление версиями:** никаких разрушительных команд (`git reset --hard`), коммиты атомарные.
