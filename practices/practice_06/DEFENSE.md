## 1. Выводы по работе (Conclusions)

В ходе выполнения практической работы была исследована безопасность учебного сервиса с интеграцией искусственного интеллекта на основе методологии Microsoft Threat Modeling и модели STRIDE. Ключевой вывод работы заключается в том, что безопасность AI-приложений не может опираться исключительно на промпт-инженерию и «послушание» языковой модели. Даже если LLM способна распознать непрямую инъекцию промпта (Indirect Prompt Injection) в пользовательских отзывах и отказаться от деструктивных действий, отсутствие детерминированных серверных проверок оставляет систему абсолютно уязвимой перед прямой манипуляцией API и атаками типа Confused Deputy / Excessive Agency. 

Построение по-настоящему защищенной архитектуры требует обязательной реализации принципа эшелонированной обороны (Defense-in-Depth): сочетания изоляции контекста на уровне промпта с жесткими серверными барьерами авторизации (RBAC, проверка владения ресурсами, параметризация запросов, валидация путей файловой системы и отказ от доверия клиентским заголовкам прав). Внедрение серверных guardrails гарантирует, что даже при полной компрометации модели или подмене ответа злоумышленником деструктивные операции (удаление файлов стенда, экспорт персональных данных по 152-ФЗ, подмена цен) физически не могут быть выполнены бэкендом.

## 2. Готовое описание для Pull Request (PR Description)

```markdown
### PR: Практика 6. Моделирование угроз и атаки с помощью LLM

#### Описание изменений
- **Модель угроз по Microsoft Threat Modeling / STRIDE**: разработана подробная модель угроз в `THREAT_MODEL.md` с архитектурной диаграммой потоков данных DFD (Mermaid), классификацией по STRIDE и разбором специфики OWASP Top 10 for LLM.
- **LLM-as-a-Judge**: в `judge-system-prompt.md` составлен кастомный промпт для независимого эксперта-судьи (`threat-judge`), проверяющего модели угроз по 10-балльной рубрике (верифицирован через `opencode` с оценкой 10/10).
- **REPORT_01 (Атаки на исходный сервис)**: зафиксированы воспроизведения 11 критических уязвимостей (SQLi, IDOR, Price Tampering, BFLA, Path Traversal, Sensitive Data in Logs, Stored XSS, Unauthorized Tool Execution, Prompt Injection) с доказательствами в `evidence/before/`.
- **Исправления в `lab/service.py`**:
  - Параметризация всех SQL-запросов (устранение SQLi в `/profile` и `/search`).
  - Серверная авторизация на основе `X-Token` сессий (устранение BOLA/IDOR в `/profile` и `/orders`).
  - Принудительное назначение цен из каталога магазина (устранение Price Tampering в `/orders`).
  - Проверка роли сотрудника строго по сессии, игнорирование клиентского `X-Role` (устранение BFLA).
  - Защита от Path Traversal и ограничение клиентов их личной папкой (устранение утечек чужих чеков и секретов).
  - Маскирование учетных данных/токенов в логах и закрытие `/debug/logs` от публичного доступа.
  - Экранирование HTML через `html.escape` (устранение Stored XSS).
  - Двухуровневая защита AI-контура: изоляция отзывов маркерами в промпте + жесткие Server-Side Guardrails в `/assistant/execute`.
- **Тесты**: добавлен набор тестов `lab/test_security.py`. Сервис успешно собирается и проходит все 31 тест через `make step6` и `make test`.
- **REPORT_02 (Повторные атаки после исправлений)**: подтверждено устранение всех 11 векторов атак с доказательствами в `evidence/after/`.

#### Выводы
Внедрение LLM в производственные сервисы требует строгого разграничения уровней ответственности: промпт-инженерия служит фильтром первого уровня, но реальная безопасность обеспечивается только детерминированными серверными проверками прав и контролем исполнения инструментов (Defense-in-Depth).
```
