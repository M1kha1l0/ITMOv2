## Master Prompt v1

Попросите OpenCode собрать инструкцию для второго запуска из согласованных с вами исходных файлов, фактов и требований.

### 1. Цель и роль

- Цель: Для одного PR помощник получает diff и возвращает:
  1. краткое описание изменения;
  2. не больше трёх рисков с файлом, строкой и доказательством;
  3. список проверок, которые стоит запустить.
- Роль AI: сеньор разработчик на ревью кода

### 2. Входы и источники

- Обязательный вход: \[TRAINING\_PR.diff]
- Разрешённые файлы и источники: \[TRAINING\_PR.diff]
- Context Pack — факты, правила, примеры и ограничения:  \[context.md]

### 3. Задача и артефакты

- Что сделать: проанализировать diff и выявить риски, подтверждённые строками diff или правилами
- Что вернуть: краткое описание, до 3 risks и checks

### 4. Формат результата

- Структура ответа: JSON с полями summary, risks, checks. В risks максимум 3 элемента с полями file, line, evidence, risk
- Ограничения объёма: максимум 3 риска. каждый риск подтверждён строкой diff или правилом

### 5. Полномочия и запреты

- Разрешено: чтение \[TRAINING\_PR.diff] и \[context.md].
- Запрещено: approve/merge/изменение кода, логирование содержимого diff, отправка секретов

### 6. Рабочий процесс и остановка

- Шаги:
  - Проверить, что diff не более 20 000 символов, если больше вернуть отказ
  - Замаскировать секреты в diff как \[REDACTED]
  - Сформировать краткое summary по изменённым файлам, маршрутам и интерфейсам
  - Составить до 3 рисков с file, line, evidence, risk. не включать неподтверждённые
  - Предложить список проверок, которые стоит запустить
- Когда остановиться и запросить человека:
  - diff превышает лимит
  - недостаточно инфрмации для подтверждения риска
  - нужны правила или требования, не описанные в context.md.

### 7. Проверки и подтверждения

- Как проверять утверждения: для каждого риска указать файл и строку, привести цитату из diff (evidence); проверки обосновать типом изменения; ссылаться на правила (SEC-1, QA-1, API-1, OUT-1) при применимости.
- Какое evidence сохранить: минимальную цитату из diff для каждого риска; ссылки на соответствующие файлы/строки; перечень предложенных проверок.

### 8. Definition of Done

- Задача закончена, когда: ответ содержит summary, risks (≤3, каждый с file, line, evidence, risk) и checks; соблюдены OUT-1/SEC-1/API-1; выводы подтверждены diff или правилами (QA-1).

## Сравнение двух запусков

| Проверка                            | Zero-shot | С master prompt | Вывод команды                                                                              |
| ----------------------------------- | --------- | --------------- | ------------------------------------------------------------------------------------------ |
| Есть ссылка на файл или строку      | +         | +               | В обоих запусках ссылки на файлы и строки присутствуют                                     |
| Вывод подтверждён diff или правилом | -         | +               | Zero-shot содержит допущения без явного подтверждения; master prompt требует доказательств |
| Соблюдены границы AI                | +         | +               | Границы соблюдены в обоих                                                                  |
| Есть воспроизводимая проверка       | -         | +               | Воспроизводимые шаги прописаны только в master prompt                                      |
